# OpenJAV implementation plan

**Goal:** A verified local multimodal Jev-compatible API and deployed bilingual documentation.
**Architecture:** FastAPI owns contract and admission; a llama.cpp client owns template/tokenizer/probability readout; CLI owns child-process lifecycle; VitePress owns the static site.
**Tech stack:** Python 3.11+, FastAPI, httpx, Pillow, pytest, llama.cpp Metal, VitePress.
**Spec:** ../specs/2026-09-21-openjav.md

## Constraints and rulings

Autonomous native execution to minimize tokens, as requested. Work in the empty project on main, as explicitly requested. Every commit uses author and committer date 2026-10-01T12:00:00-07:00. Preserve wire compatibility and real per-label probabilities. Static Pages never claims to run the model. Goal board is the durable execution ledger. One final independent reviewer, as required by executing-plans, after meaningful checks pass.

## Task 1 — API and local inference

- [ ] Write failing tests for hand-derived Noul/Choice/Score outputs, JSON/chat/image preservation, malformed or oversized images, missing probabilities, unauthorized/overloaded/dead backend, body/context limits and bad model IDs.
- [ ] Run `uv run pytest`; confirm missing product implementation.
- [ ] Implement `src/openjav/{schema,config,media,prompts,backend,service,api,cli}.py` and local playground. Add `pyproject.toml`, locked dependencies and examples.
- [ ] Run `uv run pytest` and `uv run ruff check .` until green.
- [ ] Run actual small/quality models, test 64-label readout and varied visual/text cases. Store reproducible measurements under `benchmarks/` through `scripts/benchmark.py`.

## Task 2 — Documentation and demo

- [ ] Create `site/` VitePress theme and English/Chinese quickstart, API, models, examples and benchmark pages. Generate replay from measured result JSON.
- [ ] Add correct SEO metadata, sitemap/robots/llms.txt, social image and accessible responsive styles.
- [ ] Run `npm run docs:build`. Inspect desktop/mobile pages in browser and test navigation/demo controls.

## Task 3 — Publish and audit

- [ ] Add CI, Pages deployment and bilingual READMEs, license and attribution.
- [ ] Review implementation, fix substantive findings with regression checks.
- [ ] Commit with both fixed dates, `git push -u origin main`, enable Pages, verify successful build and public English/Chinese HTTP pages.
- [ ] Recheck local health, model/image calls, source/release reproducibility, dates and the full original objective; only then complete the goal.

## Review focus

Image requests must actually use vision; arbitrary JSON must not lose metadata; every supplied option must receive a measured probability; failing child processes must not strand an apparently healthy API; documentation must distinguish live inference from recorded examples and calibrated claims from conditional scores.
