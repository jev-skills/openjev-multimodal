# OpenJev Multimodal design

An independently implemented Jev-compatible SystemOne API: `POST /v1/systemone`, `GET /v1/models`, `GET /v1/limits`, health, OpenAPI and an interactive local playground. Same request fields and typed Noul, Choice, Score results as the reference API. Alias `jev-latest` selects the active model, not TypeSafe's proprietary weights. Probabilities are normalized over the supplied choices; confidence is entropy concentration, not calibrated correctness.

Use Python 3.11+, FastAPI and llama.cpp on Metal. For each question compile the actual model chat template, disable thinking, append an answer prefix and read exactly one token's full restricted-label probability distribution. Validate 255 single-token labels using the actual backend tokenizer. Apply the same +100 logit bias to every selected label, require the complete post-sampling probability list, renormalize to cancel the bias, and disable top-k/top-p/min-p truncation and repetition penalties. Reject incomplete or invalid backend distributions; never manufacture missing labels. Sequential branches reuse the server slot's common-prefix cache when possible. Usage reports real input counts including cached tokens and one output token per question; no extra warm-up call.

Accept text, arbitrary JSON state, full text chat transcripts, top-level `images` data URLs, and chat `image_url` data URL parts. Preserve non-chat structured data, including metadata beside `messages`. Images are decoded, format-checked and resized to a configurable 1024-pixel longest edge (bounded decoded size), encoded to a sanitized PNG and passed to the vision projector. Up to 8 images supports sampled video frames, not native video/audio. Reject unsupported modalities instead of silently ignoring them. Default: no remote image fetch and no filesystem access through requests.

CLI profiles: `fast` Qwen3.5-0.8B Q4_K_M, `balanced` Qwen3.5-4B Q4_K_M, `quality` Qwen3.6-35B-A3B Q4. Match and pin projector plus weights. Benchmark fast and locally cached quality on this Mac before selecting the default. Expose optional Bearer auth, bounded request bodies/context/evaluation count, total request deadline, bounded admission, backend health, useful error envelopes. Bind localhost by default. Keep the backend private. A one-command CLI downloads pinned models, starts the backend and API, and terminates its child process cleanly. Also support connecting to an existing backend. No request logging of state/images/keys.

Bilingual static documentation: distinctive responsive landing page, quickstart, API contract, multimodal examples, model/performance guide, limitations and provenance; language alternates, canonical URLs, titles/descriptions, OpenGraph, sitemap, robots, JSON-LD, llms.txt. Interactive demo replay must label itself as recorded; optional live requests occur in the local playground. GitHub Pages only serves static assets. Real measurements are stored as JSON and never confused with upstream GPU benchmarks.

Verification: actual live API and tokenizer checks through 255 labels, real text and image requests, recorded per-request latency, docs production build, desktop/mobile visual review, GitHub CI and published-page checks. No unit-test suite, following the owner's instruction. No blanket speed/accuracy guarantee beyond observed workload. No dependency on remote paid inference.

Resource policy: serve the balanced 4B model by default with one inference slot and four CPU threads. The published quality-model benchmark displays the first 20 cases per task in the original fixed random order (180 total); the interrupted run's 886 completed receipts remain archived. No additional batch evaluation after the owner's small-sample instruction. One synthetic online Jev request verified common API shapes; it is excluded from all charts.
